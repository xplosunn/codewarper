Codewarper docs

No tools by default, no telemetry. Everything it can do, you opt into through one config file.

Getting started Configuring Skills

Getting started

Install the CLI, then run it from any project directory.

npm install -g codewarper
cd your-project codewarper
  1. Run /login to connect a provider account.
  2. Run /model to pick a model.
  3. Optional: add a codewarper.mjs to your repo (see below) to enable tools and skills.

Without a config file, the agent has no tools. It can only talk to the model you connected — which is exactly what it does until you say otherwise.

Slash commands

CommandWhat it does
/loginConnect a provider account.
/modelSwitch models.
/reloadReload the config file and skills without restarting.
/skill <name> [args…]Invoke a skill manually.
/helpList available commands.
/quit or /exitQuit Codewarper.
/<name>Run a custom command defined in your config.

Configuring

Configuration lives in a single file: codewarper.mjs in the directory where you run Codewarper. Point CODEWARPER_CONFIG at a path to use a different file. Commit it to your repo so the whole team gets the same agent. After editing it, run /reload.

KeyTypeWhat it is
toolsTool[]Tools the agent may call. Empty by default.
commandsobjectCustom slash commands: { name: { description, run(args) } }.
systemPromptstringThe system prompt the model receives.
hooksobjectCallbacks: onProviderRequest, onProviderResponse, onStartup.
skillDirectoriesstring[]Folders to load skills from (supports ~/ paths).
Tools run with your user permissions. A file tool can read what you can read; a shell tool can run what you can run. Add only what you trust, and you can read exactly what each one does — it's your code.

Example

A config that gives the agent read access and nothing else:

import { readFile } from "node:fs/promises"; export default { tools: [ { name: "read_file", description: "Read a UTF-8 text file in the current working directory.", inputSchema: { type: "object", properties: { filePath: { type: "string" } }, required: ["filePath"], additionalProperties: false, }, getCallStatusMessage(input) { return `Reading ${input.filePath}`; }, async run(input) { return await readFile(input.filePath, "utf8"); }, }, ], skillDirectories: ["skills"], };

Each tool declares its name, a JSON Schema for its input, a status message shown while it runs, and the run function itself. The local_files and local_files_with_websearch templates ship with the npm package as starting points.

Skills

A skill is a folder with a SKILL.md file that teaches the agent a repeatable workflow. List the folders in skillDirectories and run /reload to pick them up.

skills/ deploy/ SKILL.md rollout-checklist.md
--- name: deploy description: Ship a release using the project's deploy script and verify it. --- 1. Run `npm run build` and confirm it passes. 2. Follow rollout-checklist.md, step by step.
FrontmatterWhat it is
nameOptional. Defaults to the folder name. Lowercase letters, numbers, and hyphens.
descriptionRequired. The model reads this to decide when the skill applies.
disable-model-invocationOptional. Set to true so only you can invoke it via /skill.
allowed-toolsOptional. Restrict which tools the skill may use.

Invoke a skill manually with /skill <name> [args…]. Skills the model may invoke are also available to it through a built-in read_skill tool. Any other .md files in the skill folder count as supporting docs the agent can read when the skill needs them. Skill names must be unique.
